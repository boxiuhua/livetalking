# 值守数字人使用说明 —— 无人时自动讲故事 / 唱歌

让数字人在空闲时自动轮流“讲故事、唱歌”，循环不息。由外部脚本 `autohost.py` 驱动，**不修改引擎**。

---

## 一、快速开始（三步）

> 环境变量：`$py = "D:\miniconda3\envs\livetalking\python.exe"`（下同）

### 第 1 步：启动 LiveTalking 服务

```powershell
$py = "D:\miniconda3\envs\livetalking\python.exe"
cd D:\workspase\rust\LiveTalking
& $py app.py --transport webrtc --model wav2lip --avatar_id wav2lip256_avatar1
```

看到 `start http server; http://<serverip>:8010/index.html` 即启动成功。

### 第 2 步：浏览器连接（建立会话）

打开 **http://127.0.0.1:8010/index.html** → 点 **“开始连接”**，看到数字人画面。
（必须先连接，值守脚本才能找到会话来驱动。）

### 第 3 步：另开一个终端，运行值守脚本

```powershell
$py = "D:\miniconda3\envs\livetalking\python.exe"
cd D:\workspase\rust\LiveTalking
& $py autohost.py
```

数字人就会用温柔女声开始讲故事，一篇念完停顿几秒自动播下一条，循环不断。
按 `Ctrl+C` 停止值守。

## 二、放入你自己的故事和歌曲

```
content/
  stories/   # 故事文本 .txt（空行分段，逐段念）。已内置 3 篇，可自由增删
  songs/     # 歌曲音频 .wav / .mp3，放进去就会“唱”，口型自动对齐
```

- **加故事**：把 `.txt` 文件放进 `content\stories\`，用**空行**分段（每段单独念，更自然）。按文件名排序。
- **加歌曲**：把 `.wav` / `.mp3` 放进 `content\songs\`。建议 wav、16kHz 单声道最稳。目录为空则只讲故事、不唱歌。

> 为什么唱歌要放音频？TTS 只会“说”不会“唱”，所以唱歌是通过播放你预制的歌曲音频实现的
> （走 `/humanaudio` 接口），想唱哪首就放哪首的音频。

## 三、参数

```powershell
& $py autohost.py [参数]
```

| 参数 | 默认 | 说明 |
|------|------|------|
| `--gap` | `4` | 静默多少秒后播下一条 |
| `--order` | `sequential` | 播放顺序：`sequential`（顺序）/ `random`（随机）/ `alternate`（故事歌曲交替） |
| `--loop` | `true` | 播完整个清单后是否重头循环 |
| `--server` | `http://127.0.0.1:8010` | 服务地址 |
| `--sessionid` | 自动发现 | 指定会话 id（一般不用填，脚本会自动找） |
| `--content` | `./content` | 内容根目录 |

示例：

```powershell
# 故事和歌曲交替、随机停顿更短
& $py autohost.py --order alternate --gap 3

# 只播一轮不循环
& $py autohost.py --loop false
```

## 五、工作原理（简要）

- 脚本通过 `/api/admin/sessions` 自动发现浏览器建立的会话。
- 轮询 `/is_speaking` 判断数字人是否空闲；连续静默 `--gap` 秒 → 播下一条。
- 故事：按段落 `POST /human`（echo）逐段念；歌曲：`POST /humanaudio` 播整首。
- **有人打字触发对话时，数字人在说话，脚本自动让路（暂停内容），对话结束再恢复** —— 为将来接入聊天预留。

## 六、常见问题

| 现象 | 原因 / 解决 |
|------|------------|
| `未发现活跃会话，5 秒后重试` | 浏览器还没“开始连接”。先连上再等几秒即可，脚本会自动接管 |
| 数字人不出声 | 确认服务在运行、浏览器已连接、`content\stories` 里有 `.txt` |
| 歌曲不播 | 确认音频放在 `content\songs\`，格式为 wav/mp3 |
| `获取会话失败`（代理相关） | 脚本已用 `trust_env=False` 绕过系统代理；若仍异常，检查本机代理软件是否拦截了 127.0.0.1 |

## 九、推到抖音直播（虚拟摄像头方案）

数字人画面输出成"OBS Virtual Camera"，抖音直播伴侣把它当画面源开播。**已装好 pyvirtualcam + pyaudio + OBS（虚拟摄像头驱动已注册）。**

### 启动（虚拟摄像头模式，不用浏览器）

```powershell
$py = "D:\miniconda3\envs\livetalking\python.exe"
cd D:\workspase\rust\LiveTalking
& $py app.py --transport virtualcam --model wav2lip --avatar_id wav2lip256_avatar1
```

看到 `VirtualCam output started: OBS Virtual Camera` 即成功。此模式后台渲染，自动建会话 `0`。

### 让它自动讲故事/唱歌（值守）

另开终端：

```powershell
& $py autohost.py --sessionid 0
```

### 在抖音直播伴侣里开播

1. 打开**抖音直播伴侣**（PC 版）。
2. 添加素材 → **摄像头** → 选择 **`OBS Virtual Camera`**（就能看到数字人画面）。
3. 声音：在直播伴侣里**开启"捕获桌面/系统音频"**（数字人声音走系统扬声器）。
   - 更稳的做法：装虚拟声卡 VB-Cable，把数字人音频单独路由给直播伴侣。
4. 点"开始直播"。

### 重要提醒

- ⚠️ **虚拟摄像头模式下，不要再打开浏览器 index.html 点"开始连接"！** 虚拟摄像头只能被一个会话独占；浏览器连接会创建第二个会话去抢摄像头，导致崩溃、服务卡死。此模式画面直接给抖音直播伴侣看，内容由 `autohost.py --sessionid 0` 驱动，全程不用浏览器。
- **抖音合规**：平台对"AI 虚拟人/无人直播"有规则，通常要求**真人值守、标注 AI**。纯无人挂机可能被限流或封播，开播前务必看抖音直播规范。
- 虚拟摄像头只传**画面**；**声音**必须在直播伴侣里开启桌面音频捕获才能带进直播。
- 分辨率由形象素材决定（当前 576x768，竖屏，适合手机直播间）。

### 备选：直连 RTMP（不推荐先做）

`--transport rtmp --push_url rtmp://抖音推流地址`，但需要：① 安装 `python_rtmpstream`（C++库，编译麻烦）；② 抖音给你 RTMP 推流地址（个人号权限收紧，常需 1000 粉/企业号）。门槛高，优先用上面的虚拟摄像头方案。
